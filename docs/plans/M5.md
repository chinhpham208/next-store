# M5 Khu admin — Implementation Plan

> **Cho agent thực hiện:** làm từng task theo `docs/process.md` (một ticket = một nhánh `NS-xx-…` = một PR, mỗi người viết một worktree `/home/claude/wt/NS-xx`). Các bước dùng checkbox (`- [ ]`) để theo dõi. Chỉ đọc task của mình và block Interfaces của task liên quan. **Cổng 1 chưa qua:** mọi chỗ ghi "(quyết định N)" theo **đề xuất** ở mục "Cần chủ dự án quyết"; chủ dự án chọn khác thì Planner sửa task bị ảnh hưởng trước khi Orchestrator tạo ticket.

**Goal:** Admin đăng nhập bằng mật khẩu vào `/admin`; chưa đăng nhập mở `/admin/products` thì bị chuyển tới `/admin/login`, sai mật khẩu thấy lỗi, cookie phiên bị sửa tay thì bị đá ra (US-12). Admin sửa tên, giá, mô tả, tồn kho của một sản phẩm; sau khi lưu, trang của **chính sản phẩm đó** hiện dữ liệu mới ở lần tải kế tiếp, các trang sản phẩm khác không bị render lại; giá âm hoặc tên trống bị từ chối với lỗi cạnh ô nhập (US-13). Cùng mốc: sửa gốc proxy fail-open khi edge xa Neon (NS-79, kéo theo NS-56), `/cart` giữ `<title>` sau Server Action (NS-113), header bảo mật còn thiếu (CSP đầy đủ, HSTS; `requirements.md` §5), và chốt chính sách xoá sản phẩm (ADR-0014, NS-101). Không tạo / xoá sản phẩm, không đổi slug, không upload ảnh (quyết định 3; `requirements.md` §6), không đơn hàng (US-14 thuộc M6).

**Architecture:** Khu admin là cây route riêng `src/app/admin/` (ngoài `(shop)`: không header giỏ, không `CartProvider`), `noindex`. Miền mới `src/features/admin` giữ cấu hình, mật khẩu, phiên và giới hạn đăng nhập sai. **Phiên không chạm DB:** cookie `__Host-ns_admin` chứa `v1.<hết hạn>.<HMAC-SHA256>` ký bằng `SESSION_SECRET` (Web Crypto), `HttpOnly`, `Secure`, `SameSite=Strict`, hạn tuyệt đối 8 giờ (quyết định 6). `src/proxy.ts` chặn `/admin/*` (trừ `/admin/login`) **trước** lối tắt Server Action: không có phiên hợp lệ thì `GET` / `HEAD` nhận 307 sang `/admin/login`, request khác nhận 401; proxy chỉ là lớp kiểm lạc quan (Next.js 16.4.6, D2), layout admin và **mỗi** Server Action admin kiểm lại phiên. Mật khẩu là `ADMIN_PASSWORD` trong env, so sánh băm SHA-256 bằng `timingSafeEqual` (quyết định 5). Đăng nhập sai bị đếm trong bảng `admin_login_failures` (IP băm HMAC): 5 lần / 15 phút mỗi IP, 50 lần / 15 phút toàn cục thì khoá (quyết định 8), vì quy tắc rate limit duy nhất của WAF Hobby đã dành cho Server Action nói chung (ADR-0015). Sửa sản phẩm là **một** Server Action trong `src/features/products/actions.ts` (ADR-0003: mọi ghi sản phẩm gom ở `features/products`), một câu `UPDATE … WHERE slug AND updated_at = <lúc mở form>` (quyết định 13), rồi `updateTag('product:<slug>')` + `updateTag('products')`. **Tag được tách** để US-13 đúng: danh sách slug `getCatalogSlugs` (NS-109) đang mang tag `products` và mọi trang chi tiết đọc nó, nên `updateTag('products')` hôm nay render lại **mọi** trang sản phẩm; Task 4 chuyển nó sang tag riêng `product-slugs`, chỉ bị xoá khi tập slug đổi. **NS-79:** proxy thôi tra DB; nó đối chiếu một registry slug tĩnh trong repo (như blog, ADR-0012), vì ảnh sản phẩm nằm trong repo (`requirements.md` §6) nên sản phẩm mới đằng nào cũng cần deploy (quyết định 1). Header: CSP nền cho cả site theo mục "Without Nonces" của Next.js, CSP có nonce chỉ cho `/admin` (trang động), HSTS dựa vào header mặc định của Vercel (quyết định 9, 10).

**Tech Stack** (kiểm bằng `npm view` ngày 2026-11-25: `next` latest = 16.4.6, `react@19.3.1` có): giữ nguyên M4 — next 16.4.6, react 19.3.1, zod 4.6.7, drizzle-orm 0.45.4, drizzle-kit 0.31.11, postgres 4.1.1, @playwright/test 1.65.1. **Không thêm thư viện nào.** HMAC dùng Web Crypto (`crypto.subtle`), so sánh mật khẩu dùng `node:crypto` (`createHash`, `timingSafeEqual`) của Node 22. Không `@vercel/global-config` / `@vercel/edge-config` (chỉ cần nếu chủ dự án chọn 1B, khi đó "cần chủ dự án duyệt").

**Spec:** `docs/requirements.md` (US-12, US-13; §5 Bảo mật "Khu admin được bảo vệ… mọi input validate… header bảo mật cơ bản (CSP, HSTS)", SEO "trang admin `noindex`"; §6 ảnh nằm trong repo), `docs/design.md` (§5 Admin, §6, §8 M5), `docs/architecture.md` (§1 proxy "chặn /admin khi chưa đăng nhập (M5)", §2 miền `admin`), `docs/conventions.md` (§1, §2, §7, §10), `docs/process.md`, ADR-0003, ADR-0008, ADR-0009, ADR-0010, ADR-0011, ADR-0012, ADR-0013, ADR-0014 (Hệ quả "Xoá cứng sản phẩm…", NS-101), ADR-0015, ADR-0016, `docs/retro/M2.md`, `docs/retro/M4.md` (nhánh `NS-85-retro-m4`), `docs/plans/M3.md`, `docs/plans/M4.md`, ticket NS-56, NS-61, NS-79, NS-95, NS-101, NS-109, NS-113, NS-114.

## Global Constraints

- **Worktree, PR, verify:** như M4 — mỗi task một worktree `/home/claude/wt/NS-<số>`; commit Conventional Commits có mã ticket cuối dòng đầu và dòng attribution của phiên; PR bằng REST vào `develop` (`process.md` §5); `bash scripts/verify.sh quick|full`, mã thoát 3 → `verify.sh wait`; dán dòng `::pass / ::fail / ::skip` thật vào PR. Hai task song song không dùng chung cổng.
- **Cổng merge (retro M4, NS-111):** Orchestrator chỉ merge khi `bash scripts/pr-gate.sh <số PR>` thoát 0, dán output vào comment bằng chứng; skipped không phải là qua. Release PR chỉ gửi Cổng 3 khi `pr-gate.sh` (gồm `release-smoke`) thoát 0.
- **Tiết kiệm phút Actions (retro M4 đề xuất 4):** gộp ticket nhỏ không phụ thuộc nhau vào một PR khi plan ghi "gộp" (Task 1; Task 14 + 15); gộp bản sửa vào một release; không chạy lại E2E trên Dev cho commit đã chạy E2E trên preview (chỉ smoke).
- **Neon:** nhánh `preview/*` được workflow `Neon preview cleanup` tự xoá (NS-111, NS-112); vẫn giữ **tối đa 5 PR M5 mở cùng lúc** (Free 10 nhánh: `main`, `preview/develop`, mỗi PR một nhánh, chừa chỗ). Workflow fail → Orchestrator báo chủ dự án và dọn tay như `process.md` §4.
- **Role DB:** chạy được với **cả hai** cấu hình của ADR-0010 (NS-61 còn dở). Runtime chỉ DML. Bảng mới không có `serial` / identity (id do server sinh bằng `crypto.randomUUID()`).
- **Migration:** Task 5 là task **duy nhất** thêm `drizzle/*.sql`: một file expand sinh bằng `npm run db:generate`, một file backfill viết tay (`drizzle-kit generate --custom`), không `DROP`, không đổi `cart_items` / `carts`. Auditor bắt buộc. Task khác thấy cần đổi schema → dừng, báo Orchestrator.
- **DB:** ngoài `src/db` chỉ dùng `dbQuery` của `@/db`; tên truy vấn là hằng `admin.<việc>` / `products.<việc>`. Không `console.*` object lỗi, `cause`, SQL, mật khẩu, giá trị cookie, IP hay IP băm; chỉ chuỗi cố định. Ghi bị `DB_QUERY_TIMEOUT` nghĩa là không biết đã ghi hay chưa (ADR-0011): không tự thử lại.
- **Cache:** dữ liệu admin không bao giờ nằm trong `'use cache'`; trang admin đọc DB không cache, sau `cookies()` trong `<Suspense>`. Không thêm hàm `'use cache'` mới ngoài việc đổi tag của `getCatalogSlugs` (Task 4). Mọi ghi sản phẩm gọi `updateTag` theo đúng danh sách của `tagsForProductWrite` (Task 4): sửa trường → `product:<slug>` + `products`; đổi tập slug (tạo, xoá, ẩn, đổi slug — chưa có ở M5) → thêm `product-slugs`.
- **Phiên admin:** chỉ `src/features/admin/session.ts` ký / xác minh; chỉ `src/features/admin/cookie.ts` đọc / ghi cookie (trong app), proxy đọc qua `@/features/admin/proxy-api`. Cookie không chứa gì ngoài phiên bản, hạn và chữ ký. Thiếu hoặc yếu `ADMIN_PASSWORD` / `SESSION_SECRET` → khu admin **đóng** (fail-closed), không bao giờ "mở khi thiếu cấu hình".
- **Server Action admin:** mỗi action admin kiểm phiên (trừ `loginAction`, `logoutAction`) **trước** khi parse input hay chạm DB; tham số đầu vào parse bằng Zod; giá trị trả về là state có kiểu cố định, không hàng DB thô. Không action inline trong component. *Sửa theo audit PR #106 (L1):* Server Action ID là toàn cục, action gọi được qua `/admin/login` nơi proxy cho qua, nên dòng đầu **bắt buộc** là `if (!(await hasAdminSession())) return { status: 'error', error: 'unauthorized' }` (đúng dạng này: `src/admin-session-checks.test.ts` đọc AST của `src/features/admin/actions.ts`, `src/features/products/actions.ts`). File `'use server'` mới phải được thêm vào danh sách admin / shop của test đó.
- **Trang và truy vấn admin (sửa theo audit PR #106, H1):** layout **không** bảo vệ nội dung (App Router render page song song với layout; nội dung lọt vào flight payload và `.segments/*.rsc`). Mỗi `page.tsx` dưới `src/app/admin/(protected)/` là `export default async function`, dòng đầu của nó và của `generateMetadata` là `await requireAdminPage()` (từ `@/features/admin`), trước khi đọc `params` hay dữ liệu; không `await` cấp module. Mỗi hàm đọc dữ liệu admin (`src/features/products/admin-queries.ts`) bắt đầu bằng `if (!(await hasAdminSession())) throw new Error('admin: no session')`, trước kiểm slug và mọi truy vấn. `src/admin-session-checks.test.ts` kiểm cả hai.
- **Proxy:** thứ tự cố định: (1) nhánh `/admin` (kiểm phiên, không DB) → (2) lối tắt Server Action (`POST` + `next-action`) → (3) slug sản phẩm / bài viết. Proxy **không** import `@/db`, `zod`, `server-only` file nào ngoài lối vào hẹp (dependency-cruiser).
- **`"use client"`** thêm đúng các file: `src/features/admin/components/login-form.tsx`, `src/features/admin/components/product-edit-form.tsx`, `src/features/admin/components/logout-button.tsx`. Hook giữ title (Task 11) ở `src/lib/use-held-title.ts` (không cần chỉ thị, chỉ client component import). Danh sách ở `conventions.md` §2 và test danh sách (`cart-ui.test.ts` → đổi tên thành `src/client-files.test.ts`, Task 10) cập nhật cùng PR.
- **Giao diện:** tiếng Việt, token của design system, vùng chạm ≥ 44 px, tiền qua `formatPrice`. Lỗi ô nhập: phần tử lỗi có `id`, ô nhập có `aria-invalid="true"` và `aria-describedby` trỏ tới nó; lỗi chung trong `role="alert"`, lưu thành công trong `role="status"`.
- **E2E:** test ghi (đăng nhập, sửa sản phẩm, đăng nhập sai — đều là POST) gắn `@ghi`; test chỉ đọc (chuyển hướng khi chưa đăng nhập, cookie giả, `noindex`) chạy cả trên Production. Test sửa sản phẩm dùng **một** sản phẩm riêng không được spec khác dùng, chạy trong project Playwright `admin-write` phụ thuộc mọi project khác (chạy cuối), và trả giá trị về như seed trong `afterAll`.
